Build brief

Read this before the screens. It fixes the decisions the mocks assume.

Scope
A new Expo app in mobile/ with its own package.json. Three tabs — Finance, Habits, Content — plus a pushed Settings screen. No Calendar tab. The web app keeps its calendar; the phone does not get one, so no Google Calendar OAuth, no expo-auth-session, no time grids.
Backend
Same Supabase project, same tables, no schema change: finance_transactions, finance_income, habits, habit_checks, pillars, content. Port src/services/db.js across as-is — it is plain supabase-js with no DOM dependency. Same for src/constants/index.js (PILLAR_COLORS, CAT_COLORS, CATS, RATES) and the useAppData shape.
Auth
Supabase email/password, same as web. On native the client needs AsyncStorage passed in explicitly or the session is lost on every cold start:
createClient(url, key, { auth: { storage: AsyncStorage, autoRefreshToken: true, persistSession: true, detectSessionInUrl: false } })
Keep the web app's clock-skew retry (commit 3b00f96): if fetchAll throws JWT issued at future, wait 2s and retry once.
Demo mode
user === null means demo — seed from a ported defaultState and let every control work locally without writing to Supabase, exactly like the web app. Signed out is a usable state, not a wall.
Not ported
Anything DOM-bound: prompt() cell editing, contentEditable habit renaming, document.createElement HTML stripping, localStorage. Every one of those becomes a bottom sheet or AsyncStorage. Rule for the whole app: a row never edits in place — tapping it opens a sheet.
Touch floor
44×44pt minimum on everything tappable. List rows are 56pt. Destructive actions are swipe-to-reveal or inside a sheet, never a 16pt × in a table cell.
Frames
390×844 (iPhone 14/15/16 logical size). 47pt status bar, 82pt tab bar including the 26pt home-indicator inset. Take these from useSafeAreaInsets(), never hardcode.
One thing to confirm before building: these mocks are drawn light-only, matching the web app. If the mobile app should also do dark mode, say so now — it changes every token below from a constant into a pair.

Sign in

app/(auth)/sign-in.tsx · initial route

Two fields, one button, one way out. No hero, no illustration, no tab bar — the wordmark carries the identity and the eye lands on the email field. Everything sits in the lower two-thirds so the fields stay above the keyboard when it opens.

Components

B1 Month ledger · default screen

Month ledger

app/(tabs)/finance/index.tsx · initial tab

The web app's five-column table, re-cut as a ledger. Money right-aligns in one tabular column so the eye can total it going down. Days are the structure — a sticky day header with that day's subtotal replaces the repeated date cell, which is the column the phone can least afford. Category is a 9pt colour dot plus its name in the subtitle, not a chip, because the dot already carries it.

Components
FlashList (or SectionList) with one section per date, stickySectionHeadersEnabled. Rows are Swipeable from react-native-gesture-handler. RefreshControl on the list re-runs fetchAll.
Data
fetchTransactions(userId), unchanged. Rows come back already ordered by date, sort_order. Group client-side by date; row_type 'header' and 'end' are not expenses — render them as the event marker rules below.
Event markers
A header row renders as a purple rule with a flag and the label, spanning the width; the matching end row renders as a grey closing rule (see B7). They sit between day sections, never inside a list card. Everything between the two belongs to that event.
Behaviour
  • Row tap → expense detail sheet (B6). Never inline editing.
  • Swipe left reveals Delete at 76pt. Confirm with Haptics.impactAsync(Medium) + an undo toast for 4s; delete from Supabase when the toast expires, so undo costs no round trip.
  • Month pill → filter sheet (B3). Filter icon → same sheet. Chart icon → Insights (B8). Income → → Income (B9).
  • FAB → add expense (B4). It sits 98pt from the bottom, clear of the tab bar, right side for thumb reach.
  • Day headers show that day's expense subtotal, right-aligned on the same column as the rows.
Number rule
Every figure uses fontVariant: ['tabular-nums'] and two decimals. Net is signed and coloured (--green positive, --red negative); Out is red, In is plain ink — only one number per screen gets to be big.
Type badges
tx_type paid → amber paid · Name; for → blue for · Name; normal → nothing at all. The web app's — placeholder badge is dropped; empty is quieter than a dash.
Don't keep a horizontally scrolling table. Two-axis scrolling is the single worst thing on the existing mobile web build, and it's what this screen exists to replace.

B4 Add expense

Add expense

presented over app/(tabs)/finance/index.tsx

The amount is the reason this sheet exists, so it gets the 29pt tabular figure and the focus on open. Everything under it is a default someone can leave alone: today's date, just me, and the category they last used. Two taps and a number is a complete expense.

Components
@gorhom/bottom-sheet with keyboardBehavior="interactive" and android_keyboardInputMode="adjustResize". Amount is a TextInput, keyboardType="decimal-pad", autoFocus. Date opens DateTimePicker from @react-native-community/datetimepicker in spinner/inline mode.
Behaviour
  • Category defaults to the last one used, persisted in AsyncStorage — most people's expenses cluster.
  • Date shows Today / Yesterday as words before falling back to Sat 12 Sep.
  • Split opens the variant in B5. Left as Just me it writes tx_type: 'normal', person: ''.

Same rule as the web app — append within the date, and keep the value above any unclosed event end row for that date so event grouping survives.
Copy
“What was it” beats “Details”. The button says Add expense, and the row that appears is the confirmation — no toast needed on success.

Expense detail

presented over app/(tabs)/finance/index.tsx

B7 Event marker

Event marker

presented over app/(tabs)/finance/index.tsx

The web app has two separate buttons, Add Header and End Event, with the second disabled until a header is unclosed. On the phone that's one sheet: name the event, say when it starts, and close it from the same place when it's over.

Opened from
A Start an event row at the bottom of the add-expense sheet, and by tapping an existing purple marker on the ledger.
Data
Writes row_type: 'header' and, on close, row_type: 'end' with header_id pointing at it. Both go through insertTransaction untouched.
Behaviour
  • End this event is hidden while no event is open and enabled only for the unclosed one — same guard as the web hasUnclosedHeader.
  • sort_order for the end row must keep it last on its date, or later expenses on that date fall outside the event. This is the ordering bug already fixed on web in commit 4a6bef4 — port that logic, don't re-derive it.
  • Deleting a header deletes its matching end too. Expenses between them are untouched; they just stop being grouped.
Copy
“Event marker”, with one line explaining what grouping means. Nobody guesses what a header row is from its name.

B8 Insights

Insights

app/(tabs)/finance/insights.tsx · pushed from the chart icon

The web app's three charts and its Overview box, on their own pushed screen instead of stacked under the ledger. Charts are for a sit-down moment, not the 20-second expense log the tab root is built for. The donut's hole names the biggest category rather than repeating the total that's already in the heading.

Charts
react-native-gifted-charts — PieChart donut, BarChart stackData. It only needs react-native-svg, which is in the Expo SDK, so it runs in Expo Go unmodified.
Behaviour
  • Colours come straight from CAT_COLORS. Don't invent a chart palette — the dots on the ledger and the segments here have to be the same colour or neither is readable.
  • Every segment has a matching legend entry with its own figure; there are no unlabelled slices.
  • The category chips under the bar chart are the ported yearlyBreakdownCat selector. Selecting one narrows the stack to that category.
  • The current month's bar is labelled with its value and its axis letter is inked — the only emphasis in the chart.
  • Respects the ledger's month filter for the donut and totals; the bar chart is always the full year.
Accessibility
Both charts get an accessibilityLabel naming the top three values, since the marks themselves say nothing to a screen reader.
Not victory-native v40+. It renders through @shopify/react-native-skia, which pulls a native module and needs a dev build — that breaks the Expo Go requirement. Chart.js has no React Native renderer at all.

C1 Today · default screen

Today

app/(tabs)/habits/index.tsx

Six habits, six 30pt checkboxes in a 56pt row — the thing this tab is for takes one thumb and no aiming. The web app's two section headers (Weekly Goals / Daily Tracking) are gone; each habit's own subtitle says which it is and where it stands, which is more useful per row and costs no vertical space.

Components
ScrollView → week strip (7 Pressables) → today card → week card. No FlatList needed; a person has a handful of habits, not hundreds.
Data
fetchHabits(userId) + habit_checks. Keep the existing weekStart + dayIndex storage and the dateFromWeekStartAndDay / weekStartAndDayFromDate helpers from db.js verbatim — weeks start Monday, (getDay() + 6) % 7.
Three check states
  • Empty — 1.8pt border, no fill.
  • Checked — moss fill, white tick. The person ticked it on this day.
  • Goal met — pale moss fill, moss tick, --moss-light border. The weekly goal is already reached so the day needs nothing. This is the web app's auto-checked state and it must stay visually distinct from a real tick, or "done" and "didn't need doing" become the same thing.
Behaviour
  • Tap a checkbox → optimistic toggle + Haptics.impactAsync(Light) + a 120ms scale spring on the box. This is the app's one scripted animation; it confirms a tap that has no other feedback.
  • Tap a habit's name → actions sheet (C5). Long-press does the same, for reachability.
  • Week strip pips: filled moss = every habit done that day, amber = some, hollow = none. Future days are 40% opacity and not tappable.
  • “1 to go” on the right of a weekly habit is the remaining count. Habits that are done show no count — finished rows go quiet.
  • Rows sort unfinished first within their group, so the work is at the top.
Progress colours
Moss at 100%, amber below. Never red — a half-finished week is not an error.

Tokens & rules

Carried over from src/index.css so the two clients are recognisably one product. Put these in mobile/theme.ts and import them; no inline hex anywhere else.

Ground
paper #f5f3ee app background · surface #ffffff cards and sheets · surface2 #f9f8f5 pressed and inset · border #e5e3dc hairlines · border2 #d4d1c8 inputs
Ink
ink #1a1a18 · ink2 #6b6960 subtitles · ink3 #9c9990 labels, placeholders, zeroes
Accent
moss #3b6b3b — primary buttons, active tab, checked boxes, links. One accent, used only for the thing to be done next.
Semantic
green #4a7c59 income and completion · red #c0392b expenses and destructive · amber #b5720a partial progress and demo notices. Separate from the accent — a moss button is never a status.
Category
The seven CAT_COLORS values verbatim: Transport #a8c4e0 · Food #c8ddb8 · Events #d4b8d4 · Misc #d4c8a0 · Clothes #e8b8c0 · Recurring #a8d4cc · Gifts #e8c0c8. Used for dots, donut slices and stacked bars alike.
Pillar
The eight PILLAR_COLORS {bg, text} pairs verbatim, addressed by colorIdx.
Type
DM Sans throughout via @expo-google-fonts/dm-sans. Titles 26/700/−0.03em · screen titles 19/600 · sheet titles 18/600 · body 14.5/500 · subtitle 12/400 · label 11.5/500. Nothing under 11. No uppercase labels — the web app's tracked-out caps are dropped in favour of sentence case.
Numbers
Every figure gets style={{ fontVariant: ['tabular-nums'] }}. Money always two decimals. Large currencies through Intl.NumberFormat.
Shape
Sheets 26 · cards 14–16 · inputs and buttons 12–13 · chips 999 · checkboxes 10. Radius indicates what kind of object something is, so don't flatten it to one value.
Spacing
16pt screen gutter · 8–9pt between cards · 13–15pt inside cards · rows 56pt, settings rows 52pt.
Touch
44×44pt minimum, no exceptions. FAB 56pt at 18pt from the right, 98pt from the bottom.
Safe areas
useSafeAreaInsets() for both ends. The 47pt status bar and 82pt tab bar in these frames are an iPhone 15 — read them, never hardcode them.
Shadow
Only three things cast one: the FAB, an open sheet, and a card being dragged. Everything else separates with a hairline. Shadows on every card is what makes a layout look flat.
Motion
Sheet presentation, the checkbox spring, the ring completing, and list reordering. That's the list. No entrance animations on lists or cards, and everything checks AccessibilityInfo.isReduceMotionEnabled().
Haptics
Light on a check or a successful save · Medium on drag pick-up and swipe-to-delete · Success only when a day completes · Warning on a rejected sign-in. Nothing else vibrates.
Logo
public/logo.png — the UD monogram, 500×500 with an opaque white field. Use it on the sign-in and loading screens at 36pt. The web app composites it with mix-blend-mode: multiply to sink the white into the paper ground; React Native has no blend mode, so export a transparent-background PNG for mobile/assets/logo.png rather than shipping the white square. Same asset drives icon, splash.image and adaptiveIcon.foregroundImage in app.json, with backgroundColor: "#f5f3ee".
Dark mode
Out of scope. The app is light-only, like the web version. userInterfaceStyle: 'light' in app.json so the OS doesn't recolour native controls underneath a light UI.
The three rules that matter most: a row never edits in place — it opens a sheet; every tappable thing clears 44pt; every figure is tabular. Most of the friction on the current mobile-web build traces to one of those three.

Build order

Five passes, each one leaving something usable on a phone.

1 · Shell
Expo app, theme.ts, DM Sans, GestureHandlerRootView, Supabase with AsyncStorage, auth gate, sign-in, three empty tabs. Done when signing in on Expo Go lands on a Finance tab and survives a cold start. Screens A1–A3, E1–E2.
2 · Finance ledger
Port db.ts, build the date-grouped list, stat cards, swipe-to-delete with undo, the filter sheet, add-expense and detail sheets. Done when an expense logged on the phone appears in the web app on refresh. B1–B6.
3 · Habits
Week strip, today card, the three check states, back-fill, add/actions sheets, archived. Done when a Tuesday tick made on Saturday shows on Tuesday in the web grid — that's the one place the (weekStart, dayIndex) mapping can quietly go wrong. C1–C7.
4 · Content
Idea cards, pillar chips, detail and stage sheets, pillar management, then reorder mode last since it's the only piece needing Reanimated gestures. Done when a drag on the phone and a drag on the web produce the same order. D1–D9.
5 · Trim
Insights charts, income screen, converter, event markers, every empty state, haptics, the reduce-motion checks. These are all real, and none of them blocks daily use. B7–B12.
Worth writing tests for, even in a personal app: the habit week mapping (dateFromWeekStartAndDay ↔ weekStartAndDayFromDate), sort_order around event end rows, and the currency conversion. Everything else is visible the moment you look at the screen; those three fail silently.
